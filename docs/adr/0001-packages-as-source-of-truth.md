# 0001: Release packages are the source of truth

Status: accepted, implemented

## Context

Possible inputs: the OPNsense documentation (API pages), the git
repositories `opnsense/core` and `opnsense/plugins` at release tags, or the
packages on `pkg.opnsense.org`.

- The documentation is generated by hand from `master` and is not tied to
  a release.
- Git tags exist for core releases, but not for plugins as shipped per
  series, and not for hotfix revisions (`26.7.8_2`).
- Packages contain exactly what runs on a firewall, are signed, and list
  build commits.

## Decision

Read the signed catalog and packages of each release snapshot. Verify the
catalog signature and every package checksum before extracting anything.

## Consequences

- Plugins and hotfix revisions are covered.
- Depends on the mirror layout (`MINT/` snapshots, ABI paths) and package
  formats, which are not documented as stable interfaces; changes there
  must fail loudly (they did once: xz -> zstd, SHA-256 -> BLAKE2b, both
  handled).
- Downloads are large (about 1 GB for 33 releases with plugins); a cache is
  required.

## Evidence

The `safesearch` field moved in 25.7.8 (found by the release matrix); a
comparison of only the git tags 25.7 and 26.1 suggested 26.1.
